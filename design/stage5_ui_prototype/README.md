# 阶段 5A：操作界面交互设计稿（纯设计产物）

> **可丢弃原型，未经 TDD，不得直接固化上线。**

本目录是一套纯本地、逐屏静态 HTML 交互设计稿，用来验证一件事：一个不使用终端、不了解技术细节的项目负责人，能否只看界面完成一个演示批次从新建到关账的完整旅程。

本阶段只呈现产品形态，不连接任何后台，不运行任何真实流程，也不保存用户输入。

## 打开方式

双击 `index.html`，再按页面中的顺序逐屏查看。

无需安装软件、启动服务或连接网络。每个 HTML 都是自包含文件，样式写在文件内部，没有外部字体、图片、脚本或内容依赖。

## 产品定位

- 界面类型：产品工具，不是营销页面。
- 主要用户：不具备编程基础的项目负责人或运营人员。
- 主要任务：始终知道批次走到哪里、下一步是什么、是否受阻、是否会产生费用，并在 QC 后完成终审关账。
- 成功标准：用户不看文档、不开终端，也能独立走完整个演示批次。
- 性格：沉着、可信、直接。
- 明确避免：一键全自动、隐藏费用、技术术语堆叠、只靠颜色表达状态、密钥输入框、多人协作、权限、通知中心、分析报表。

## 视觉与无障碍规则

使用场景是白天办公室里的长时间任务处理：界面以纯白和浅冷灰承载信息，用克制的钴蓝标识主要动作，状态色只用于成功、提醒、待复核和失败。

- 系统字体，不加载外部字体。
- 正文字号不小于 14px，正文与背景保持高对比。
- 状态同时使用文字、图形和颜色，不只靠颜色区分。
- 所有可点击元素都有清晰焦点状态。
- 移动窄屏时侧栏变为横向导航，表格允许水平滚动。
- 动效只用于悬停与状态反馈；用户选择“减少动态效果”时取消过渡。
- 卡片圆角不超过 16px，不使用装饰性玻璃、渐变文字或大面积阴影。

核心颜色均以 OKLCH 定义：

- 页面：`oklch(1 0 0)`
- 次级表面：`oklch(0.975 0.006 250)`
- 正文：`oklch(0.22 0.025 250)`
- 主操作：`oklch(0.55 0.149 250)`
- 成功：`oklch(0.50 0.13 150)`
- 提醒：`oklch(0.64 0.14 80)`
- 失败：`oklch(0.53 0.17 25)`

## 屏幕清单

| 屏幕 | 文件 | 目的 |
|---|---|---|
| 导航 | `index.html` | 按完整旅程进入各屏，并打开三份配套说明 |
| S1 | `s1_batch_list.html` | 查看批次与下一步提示 |
| S2 | `s2_new_batch.html` | 填写产品编号、七项确认信息和输入资料 |
| S3 | `s3_batch_overview.html` | 看懂进度、阻塞和唯一下一步 |
| S4 | `s4_output_declaration.html` | 声明需要的产出并填写批次备注 |
| S5 | `s5_execution_confirm.html` | 执行前预检与真实费用二次确认 |
| S6 | `s6_running.html` | 查看运行中状态和友好时间线 |
| S6 成功态 | `s6_success.html` | 查看成功结果与下一步 |
| S6 失败态 | `s6_failed.html` | 查看失败终态，不自动重试 |
| S7 | `s7_qc_review.html` | 查看 14 图 QC、逐条裁定并关账 |
| S8 | `s8_failure_help.html` | 获取脱敏解释、技术详情和受控重试指引 |
| S9 | `s9_completed.html` | 查看最终交付物与保存位置 |

S6 的三个文件是同一个业务屏幕的三种静态状态，不扩大九屏范围。

## 设计边界

- 没有连接后台、Canvas Agent、模型或图片服务的代码。
- 没有外部网络请求。
- 没有密钥输入、显示或存储。
- 没有自动重试或一键全自动。
- 没有多人协作、权限、通知中心或数据分析报表。
- 原型中的保存、执行、裁定、下载等动作只表达预期交互；真实能力以 `contract_map.md` 为准。

## 配套文档

- `contract_map.md`：每个界面动作对应的事实来源、白名单通道或新契约提案。
- `backend_gaps.md`：阶段 5B 前必须补齐的后台缺口，按优先级排序。
- `hosting_options.md`：放进 Infinite Canvas fork 或做独立操作面板的对比与建议。

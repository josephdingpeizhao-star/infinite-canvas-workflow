详情图可以更强调信息解释、局部质感、场景代入和卖点表达，但不能变成杂乱的信息图，也不能牺牲产品真实感。
每一张详情图只聚焦一个核心信息，不要一张图同时塞入过多卖点。

四、页面任务必须由角度反推

八、道具关系规则

生成详情图【单张变量配置】时，必须严格遵守项目源文件中的《道具生成规则模块》。

每一张图的“道具关系”项不需要重复完整道具规则，只需根据该张页面任务，写出本张道具的功能方向、数量范围、允许类型与禁止遮挡要求。
每一张图的“道具生成”项都必须加上，所有的道具必须真实自然，带有现实世界中的微瑕疵感，不得过度美化。

详情图中的道具必须服务信息解释。
道具可以用于说明使用场景、尺寸比例、材质对比、套装搭配和生活方式。
道具不得为了丰富画面而随意堆叠。
道具不得遮挡产品关键轮廓。
道具不得通过摆放、遮挡或引导关系强迫产品变换角度。
如果本张详情图是结构说明或材质特写，可以只使用少量道具。
每套【本张变量配置】均需在【道具生成】或【道具关系】、【背景与光线】、【真实感要求】中体现：产品本身以外的背景、道具、桌面、布料、纸张、食物、手部和环境光影，可以保留现实世界轻微不完美，例如自然褶皱、轻微纹理、纸张轻微翘边、食物自然不规整、道具微小摆放偏差、真实接触阴影和轻微自然光影变化，用于避免画面过度干净、过度美化、过度棚拍和过度合成感。该规则不得作用于产品本身，不得让产品出现原图不存在的污渍、划痕、裂纹、破损、做旧、掉色、釉面瑕疵、图案磨损、结构变形或材质变化，也不得改变产品结构、比例、颜色、材质、纹理、图案和配件关系。

九、文字信息规则

详情图可以使用文字，但文字必须服务本张页面任务。

建议每张详情图最多包含：
一个主标题；
一个短副标题；
2 至 4 个简短卖点。

文字必须与当前画面可见内容相互支持。
不要在文字中宣称当前画面无法支持的结构细节、材质细节、容量信息或使用价值。
文字不能遮挡产品主体，不能破坏真实摄影感，不能让画面变成促销海报或复杂信息图。
如果本张图不适合放文字，请明确写“本张图不设置文字信息”。

【中文营销文案规则】
当本张详情图需要文字时，必须生成符合中文淘宝天猫详情页语境的营销说明文字。
详情图文字可以比主图更信息化，但每张只围绕一个核心页面任务。
建议包含一个主标题、一个短副标题、2 至 4 个简短卖点；所有文字必须简洁、自然、可读。
中文营销文案只能依据《产品身份档案》已确认内容和《商品信息补充清单》中的四项字段：商品名称、尺寸信息、容量信息、中文营销文案。

如果文字任务与产品角度或画面证据冲突，应删减文字，而不是改变产品角度或产品结构。
产品尺寸标注图允许出现尺寸参数文字，但只允许使用《产品身份档案》中已确认的真实尺寸字段。
不得宣称未确认的高度、口径、容量、重量、配件尺寸或比例关系。
最终出图只渲染【中文营销文案】和【尺寸标注信息】中列出的文字，不得自行新增尺寸数字。
不得把“未提供”“资料缺失”“本张不生成该项”等流程说明写入【中文营销文案】，也不得要求最终出图渲染这些说明。不得使用“官方认证”“全网第一”“行业最强”“销量领先”“无理由退换”等无法核验表达。

十三、手持场景启用规则

本节用于在标准 8 套或旧版 7 套详情图变量配置中引入手持产品场景。手持场景是可选分支，不是每套配置的默认结构。标准模块归属包含模块05的产品尺寸标注图位一律不得启用手持场景，也不得调用动态手持样式参考图；这项硬约束优先于手持名额分配，手持名额只在标准模块归属不包含模块05的图位之间分配；建批已将详情图手持上限限制为详情图张数 N−1，因此二者不会冲突。

【手持启用计划】
生成详情图变量配置前，必须先执行手持启用计划；若用户明确指定详情图手持数量，或明确指定整批手持数量且上游已分配到详情图数量，则该数量是本阶段硬性目标。
读取《产品身份档案》的【产品真实尺寸】和尺寸置信度，读取角度入库表中各槽位的适合任务和遮挡风险。
手持启用计划只分配给适合生活使用、比例感或交互展示的模块；标准模块归属包含模块05的规格尺寸与容量图或尺寸标注图位一律不得启用手持，也不得调用动态手持样式参考图，且不计入手持启用名额；这项硬约束优先于手持名额分配，手持名额只在标准模块归属不包含模块05的图位之间分配；建批已将详情图手持上限限制为详情图张数 N−1，因此二者不会冲突；模块06质感可信视觉呈现图和模块08收尾氛围图通常不启用手持。
无用户明确数量要求时，若产品尺寸置信度为中或高，且至少 3 套页面任务与角度槽位适合手持，则默认生成约 3 套启用手持，其余不启用；标准模块归属包含模块05的产品尺寸标注图位一律不得启用手持，不得调用动态手持样式参考图，也不计入手持启用名额；这项硬约束优先于手持名额分配，手持名额只在标准模块归属不包含模块05的图位之间分配；建批已将详情图手持上限限制为详情图张数 N−1，因此二者不会冲突。
无用户明确数量要求时，若适合手持的角度或页面任务不足 3 套，则按可安全启用的上限生成手持，并在批次末尾输出【手持启用数量说明】。
无用户明确数量要求时，若产品尺寸置信度为低或无法确认，不得强行启用手持，但必须在【手持启用数量说明】中写明”因尺寸无法确认 / 低置信度，本批次不启用手持”，并按实际生成套数统计，不得静默全部写成不启用。若用户明确指定手持数量，尺寸低置信、结构风险、角度风险、模块职责或安全表现不足只能触发阻断反馈或补充信息请求，不得自动把用户要求的手持配置改成非手持。
不得为了默认凑数让不适合手持的角度强行手持，也不得为了简化生成把所有可手持配置一刀切取消；但用户明确指定数量时，不得用“默认约 3 套”“尺寸不明默认不启用”或“模块通常不启用手持”静默覆盖用户数量。

1. 启用数量（默认建议与用户明确数量）
单品批次的详情图变量配置中，在用户没有明确指定手持数量时，默认目标为约 3 套启用手持，其余不启用；标准模块归属包含模块05的产品尺寸标注图位或规格尺寸图位一律不得启用手持，也不得调用动态手持样式参考图，质感可信图和收尾氛围图通常不启用手持；模块05硬约束优先于手持名额分配，手持名额只在标准模块归属不包含模块05的图位之间分配；建批已将详情图手持上限限制为详情图张数 N−1，因此二者不会冲突。用户明确指定手持数量且作用范围为详情图时，必须生成对应数量的详情图手持配置；用户明确指定整批手持数量但未分配主图 / 详情图范围时，必须先反馈确认，不得自行拆分。该默认手持目标使详情页既能解释产品结构、材质、容量等纯静物信息任务，也能解释生活使用场景、比例感等手部互动信息任务；该目标在尺寸中高且角度适配时应执行。只有无用户明确数量要求且尺寸、角度、产品结构、页面任务、详情页模块职责或真实感存在明确冲突时，才可低于默认 3 套，并必须解释。最终启用手持的套数在无用户明确数量要求时先服从产品真实尺寸与尺寸置信度，再综合产品类型、角度槽位、页面任务和真实感判断：
若产品真实尺寸无法确认或尺寸置信度为低，且用户没有明确手持要求，本批次可以 0 套启用手持，并在“启用数量说明”中说明原因；
若详情页主线是结构、材质、容量、套装关系等纯静物信息，可以少于 3 套，甚至 0 套；
若详情页主线是使用场景、生活方式、比例感、礼物属性，也可以多于 3 套；
若最终启用数量与”约 3 套”明显偏离，必须在本批次输出末尾用一段”启用数量说明”解释偏离原因（例如”本批详情图任务侧重材质质感与结构说明，仅 1 套使用生活场景，故只有 1 套启用手持”）。
不得为了默认凑数让纯结构说明类配置强行启用手持，从而干扰信息任务；也不得为了简化生成而把所有应启用手持的配置一刀切去掉。若用户明确指定数量但某些模块或角度无法可靠承接，必须输出阻断反馈或要求补充可用角度 / 尺寸信息，而不是少生成手持配置后继续交付。

3. 条件引用关系
某一套配置启用手持场景后，该套配置才引用《手持产品场景基础模块》与《手持适配规则》。《手持产品场景基础模块》提供手与产品交互的通用底层约束，包括产品身份锁定、接触关系、遮挡控制、角度服从、静态握持与动态拿起的边界；《手持适配规则》按产品类型给出具体的合理持握位置、禁止持握位置、允许遮挡区、必须保留可见区、是否离桌、单双手裁定。不启用手持场景的配置不引用这两份文件，其【手持交互声明】栏写”本张图不启用手持场景”。

4. 套装批次的差异
本节”默认建议约 3 套”的规则仅适用于单品批次。套装批次不适用本节数量目标，套装手持规则以《套装产品工作流补充规则》第七节和《套装变量配置补充模块》【手持交互声明】条目为准。

3. 与角度规则的兼容
手持场景必须服从既有角度槽位体系。手部动作适配本张【绑定角度槽位】对应的白底产品图角度，不得为某种握姿要求产品旋转、翻转、改变朝向、改变壶口可见程度、壶身外壁透视或壶底与底足可见关系。若某个握姿必须依赖另一个角度才能成立，应将该套配置改绑更合适的槽位，或改用其他握法，而不是旋转产品。
槽位适配倾向：45°斜侧视槽位适合表现握住壶柄或提梁、手托壶底、扶壶身外壁和生活使用感；侧面低角度槽位适合表现拿起动作、壶身高度、壶柄或提梁轮廓和壶底/底足支撑；正面微俯视槽位可用，但持握位置要避开正面图案和壶口核心轮廓；顶部俯视槽位主要用于壶口、壶内壁、液面和内容物展示，通常不适合大面积手持，如启用只能让手轻扶壶口边缘外侧或托住边缘下方，且不得遮挡壶口、壶内壁或内容物。启用手持的若干套应优先落在适合的槽位上，不得为了使用手持而强行选用不适合的槽位。

4. 与产品主体的兼容
手是画面互动元素，不是画面主体，也不是道具。手不得遮挡产品核心识别区域，包括正面主体图案、壶口轮廓、壶口边缘厚度、壶身器型、壶内主要可见区域与配件连接关系；手不得大面积包裹产品，不得抢夺视觉中心。手持详情图的视觉中心仍是产品，手只作为辅助交互元素存在。手不计入《道具生成规则模块》的道具数量，【手持交互声明】栏与【道具关系】栏互相独立。

5. 与详情图任务的兼容
手持场景适合承担生活使用场景、日常使用比例感、单品与场景使用关系类的详情页信息任务，不适合承担纯结构说明、纯材质特写类任务。手在详情图中还可作为产品大小的比例参照。手持子场景在静态握持与动态拿起之间选择：静态握持表现产品被稳定握住、托住或扶住；动态拿起表现产品刚被拿起、轻微离桌的瞬间。详情图不追求大幅度动作，动态拿起的离桌幅度应小而明确。
当手部交互会削弱产品清晰展示或干扰本张信息任务且无法兼顾时，无用户明确手持数量要求的配置应缩小动作幅度，或取消该套配置的手部、改用非手持方案，相应减少启用手持的套数；用户明确指定手持数量时，不能直接取消该套手部并继续交付，必须改选可承接手持的任务 / 槽位，或输出阻断反馈与补充信息请求。

十四、输出任务

请基于以上规则，默认一次性生成 8 套淘宝天猫电商详情图【单张变量配置】，并覆盖模块01至模块08。如果用户明确要求 7 套，则启用【旧版 7 套兼容模式】，输出【模块合并说明】，且不得省略首屏承接、核心卖点、使用场景、细节质感、规格尺寸和收尾氛围等核心视觉任务。

每一张变量配置必须主动适配对应角度槽位。
每一张详情图只聚焦一个核心页面信息。
8 张详情图之间必须形成明确差异；旧版 7 套兼容模式下 7 张详情图之间也必须形成明确差异，不能只是更换文字或少量道具。
如果某个页面任务与对应角度槽位不匹配，请自动调整页面任务或展示重点，而不是保留冲突要求。
如果需要重复调用同一合格角度槽位，可以重复调用，但必须通过页面任务、构图、镜头距离、产品占比、文字信息、道具功能和背景层次形成差异。

所有详情图变量配置的【手持交互声明】栏必须全部保留：启用手持的配置，须依据《手持产品场景基础模块》与《手持适配规则》写明手持子场景类型、产品类型、持握或托举的部位方向、是否离桌及离桌幅度、单手或双手；不启用手持的配置，该栏写”本张图不启用手持场景”。标准模块归属包含模块05的产品尺寸标注图位一律不得启用手持，该栏必须写”本张图不启用手持场景”，且【动态手持样式参考图调用】必须写”无”；这项硬约束优先于手持名额分配，手持名额只在标准模块归属不包含模块05的图位之间分配；建批已将详情图手持上限限制为详情图张数 N−1，因此二者不会冲突。手持场景仅作为可选分支，不得让全部配置默认包含手持元素，也不得不写【手持交互声明】栏。

无用户明确手持数量要求时，启用手持的数量以”默认目标约 3 套、最终由产品真实尺寸、尺寸置信度与角度适配综合判断”为准（详见第十三节）。有用户明确手持数量要求且作用范围为详情图时，批次末尾必须输出【手持启用数量说明】，写明用户要求数量、实际启用手持数量、不启用数量、是否完全满足用户数量；未满足时必须写明阻断原因或待补充信息，不得写成普通默认偏离原因。

【代码块输出强制规则】
每一套变量配置必须单独输出为一个可一键复制的 Markdown 代码块。
每个代码块只能包含一套【本张变量配置】及其对应的最终出图固定开头。
禁止把 2 套、6 套、7 套或 8 套变量配置合并进同一个代码块。
禁止在一个代码块内连续输出“详情图 1 至详情图 8”“详情图 1 至详情图 7”或“主图 1 至主图 6”。
输出格式必须为：
## 详情图 1

```markdown
此处仅放详情图 1 的完整变量配置
```

## 详情图 2

```markdown
此处仅放详情图 2 的完整变量配置
```

标准完整详情页模式依次类推，直到：

## 详情图 8

```markdown
此处仅放详情图 8 模块08收尾氛围与风险克制的完整变量配置
```

旧版 7 套兼容模式则输出至“## 详情图 7”，且必须在批次中输出【模块合并说明】。

主图同理使用“## 主图 1”“## 主图 2”，主图仍为 6 套。
详情图套装批次同样适用该规则，不因套装栏目增加而把多套配置合并进同一个代码块。

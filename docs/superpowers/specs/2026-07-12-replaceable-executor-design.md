# 可替换执行器边界设计

## 目标

让画布运行台与具体模型、供应商和执行引擎解耦。上层业务只提交统一执行请求并接收统一结果；Codex、GPT Image 2 或未来其他服务都作为可替换适配器存在。

## 用户可感知行为

- 画布命令、三段门禁、事件日志和节点状态保持不变。
- 切换执行器不改变工作流步骤名称或业务产物定义。
- 未配置服务端密钥时，请求在调用外部服务前安全失败。
- API 密钥只从服务器环境变量读取，不进入仓库、画布、事件日志或异常消息。

## 边界

```text
画布运行台 / 业务路由
        |
        v
统一 ExecutionRequest / ExecutionResult
        |
        v
ExecutorRegistry（按名称选择适配器）
        |
        +-- demo（保留现有演示能力）
        +-- openai-image（GPT Image 2）
        +-- future-provider（未来扩展）
```

业务层不得导入供应商 SDK、拼接供应商 HTTP 请求或解析供应商响应。供应商适配器不得判断工作流能否运行，也不得修改画布门禁。

## 第一阶段范围

1. 定义供应商无关的执行请求、图片任务、执行结果和执行器协议。
2. 建立显式注册表和组合入口；未知执行器必须拒绝。
3. 把现有 demo 执行器适配到统一协议，保持原行为。
4. 增加纯 Python 标准库的 GPT Image 2 适配器：
   - 无参考图时使用 `/v1/images/generations`。
   - 有参考图时使用 `/v1/images/edits`。
   - 默认模型 `gpt-image-2`，可在适配器配置中替换。
   - 密钥只读 `OPENAI_API_KEY`。
   - HTTP 传输可注入，自动测试不访问真实网络。
5. 当前真实批次仍受仓库门禁保护；本阶段不生成图片、不调用付费 API。

## 暂不包含

- 公司登录、权限、任务队列和数据库。
- 产品身份建档等文本/视觉大模型适配器。
- 从现有最终提示词产物自动构造批量图片任务。
- 真实付费调用、真实图片输出和生产部署。
- ComfyUI 接入或 Infinite Canvas fork 修改。

## 验收

- 上层仅依赖统一契约和注册表。
- 新增供应商时无需修改画布命令解析和门禁代码。
- demo 行为测试继续通过。
- GPT Image 2 的请求形状、Base64 解码、错误处理、密钥缺失和参考图 multipart 均有离线测试。
- 全仓库测试通过，且没有新增第三方依赖。
